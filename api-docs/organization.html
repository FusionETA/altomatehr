Organization

The company the key belongs to: its settings, its logo, the signatures it prints on letters, the modules its plan enables, who administers it, and a hand-off that drops one of those administrators into AltomateHR already signed in. A key can only ever reach its own company; there is no company id to send.

This page's errors don't all use the shapes on the overview. Where an action refuses a request itself, it answers 400 or 404 with { "message": "…" } (a plain message string), not error. Field validation (errors) and 403 (error.message) are as on the overview. The logo upload and the signature endpoints refuse with { "error": "…" } instead. Each endpoint below says which it returns.

Company settings

No plan module is needed for these endpoints, or for the logo and signature ones below: every company can read and edit its own settings.

PUT /organizations/current organizations:write

Update the company's name, currency, mileage, geofence and working-hours settings.

Request body

FieldTypeRequiredMeaning

defaultCurrencystringsee noteExactly 3 characters. Trimmed and stored upper-case. Default "MYR".
defaultMileageRatenumbersee note0 – 100. Default 0.
mileageUnitstringsee note"KM" or "MILE". Default "KM".
geofenceRadiusMetersintegersee note10 – 100000. Default 200.
workingDaysstring | nullnoCSV of weekday numbers 1–7 (Monday = 1), max 20 characters. Null or blank means Monday to Friday. The server doesn't check the digits. Leave counts only these days, so a Friday-to-Monday request costs 2 days, not 4.
workingHoursStartstringsee note"HH:mm", 24-hour. Default "09:00". Must be earlier than the end.
workingHoursEndstringsee note"HH:mm", 24-hour. Default "18:00".
lunchBreakMinutesintegersee note0 – 480. Default 60.

see note: the request isn't rejected when the field is left out, but its default is then saved. See below.

Response 200

The updated organization object.

Errors

  • 400 { "errors": { … } } — a field is out of range, malformed, or not a valid mileageUnit.
  • 400 { "message": "Working hours start must be before end." }
  • 400 { "message": "Xero is not subscribed to … " } — the company has Xero connected and defaultCurrency is not one of the currencies Xero holds. The message lists the ones it does. Without Xero connected, any 3-letter code is accepted.
  • 403 — the key lacks organizations:write.
  • 404 — empty body; the company no longer exists.
This replaces every field above, it doesn't merge. The change is recorded in the company's activity log.

Company logo

The company's logo, printed top-left on the letterhead of every PDF letter from the Documents page. A company has at most one. The image is never at a public URL: it is only served by GET /organizations/current/logo with a key, and hasLogo / logoUpdatedAt on the organization object say whether there is one. No plan module is needed.

GET /organizations/current/logo organizations:read

Download the company's logo image.

Response 200

The image bytes, not JSON. Content-Type is image/png, image/jpeg or image/webp, read from the file's own bytes. Cache-Control: no-store, so don't cache it; use logoUpdatedAt to decide when to fetch again.

Errors

  • 403 — the key lacks organizations:read.
  • 404 — empty body; the company has no logo (or its stored file is missing or unreadable).
curl https://<api-host>/organizations/current/logo \
  -H "Authorization: Bearer wp_live_xxx" -o logo.png
PUT /organizations/current/logo organizations:write

Upload the company's logo, replacing any previous one.

Request

multipart/form-data with one file field named file. The file's type is decided from its bytes, not its name or the Content-Type you send.

RuleLimit
FormatPNG, JPEG or WebP. SVG and GIF are refused.
File sizeAt most 2 MB (2,097,152 bytes).
DimensionsAt most 4000 pixels on each side.
IntegrityThe whole file must be present and readable. A truncated or damaged image is refused, even if its header looks fine.

Response 200

The updated organization object, with hasLogo: true and a new logoUpdatedAt. It is 200, not 201, also for the first upload.

{
  "id": "org_123",
  "name": "Example Sdn Bhd",
  "...": "the other organization fields",
  "hasLogo": true,
  "logoUpdatedAt": "2026-01-15T08:30:00Z"
}

Errors

The 400 bodies here use { "error": "message" }, unlike the other Organization actions.

  • 400 { "error": "Choose an image file (PNG, JPG or WebP) to upload." } — no file part, or it is empty.
  • 400 { "error": "The logo is larger than 2 MB. Use a smaller image." }
  • 400 { "error": "The logo must be a PNG, JPG or WebP image." } — any other format.
  • 400 { "error": "The logo is 5000 × 3000 pixels. Keep each side to 4000 pixels or less." } (the message carries the real size).
  • 400 { "error": "That image can't be read. It may be damaged — try saving it again." } — truncated or corrupt file.
  • 403 — the key lacks organizations:write.
  • 404 — empty body; the company no longer exists.
  • 413 — the whole request body is over 3 MB. This is a hard cap on the request, checked before the 2 MB rule, so a file between 2 and 3 MB gets the 400 message above and a larger one gets 413 with no JSON body.
  • 415 — the request isn't multipart/form-data.

Things that bite

  • It replaces, it doesn't add. The previous logo file is deleted. Letters already generated and kept on file keep the logo they were printed with; only letters made after this call use the new one.
  • It is a settings change. The same switch as PUT /organizations/current gates it for a signed-in admin (the owner's “Change settings” access). An API key always has it, so a key is never refused for that reason. Each upload is recorded in the company's activity log.
curl -X PUT https://<api-host>/organizations/current/logo \
  -H "Authorization: Bearer wp_live_xxx" \
  -F "file=@logo.png"
DELETE /organizations/current/logo organizations:write

Remove the company's logo. Letters generated afterwards print the letterhead without one.

Response 204

Empty body. Also 204 when there was no logo, so it is safe to repeat.

Errors

  • 403 — the key lacks organizations:write.

Removing a logo is recorded in the company's activity log, and the file is deleted.

curl -X DELETE https://<api-host>/organizations/current/logo \
  -H "Authorization: Bearer wp_live_xxx"

Letter signatures

A company can keep up to 10 saved signatures: an image plus the signatory's name and position. A Documents letter prints the one chosen for it above the signature line. These endpoints manage the saved set; choosing one for a letter is done with signatureId on the Documents preview and generate calls. Like the logo, the image is never a public URL: it is served only by GET /organizations/current/signatures/{id}/image and is never cached.

Reads need organizations:read; changes need organizations:write. Changes are a settings change like PUT /organizations/current: for a signed-in admin they need the owner's “Change settings” access, and an API key always has it, so a key is never refused for that reason. Every add, edit and remove is recorded in the company's activity log. Another company's signature id is simply a 404.

The signature object

FieldTypeMeaning
idstringSignature id. Use it in the endpoints below and as signatureId / defaultSignatureId on Documents.
namestringThe signatory's name, printed under the image. Max 120 characters.
positionstringThe signatory's position, printed under the name. Max 120 characters.
isDefaultbooleantrue for the company default. At most one signature has it.
createdAtstringISO 8601 UTC time it was added.
createdByNamestring | nullWho added it, as their name read at the time. May be empty when a key added it.

POST /organizations/current/signatures organizations:write

Save a new signature.

Request

multipart/form-data with these parts. The image's type is decided from its bytes, not its name or the Content-Type you send.

PartTypeRequiredMeaning
filefileYesThe signature image. PNG, JPEG or WebP (SVG and GIF are refused), at most 1 MB (1,048,576 bytes), at most 4000 pixels on each side, and fully readable — a truncated or damaged file is refused.
nametextYesMax 120 characters after trimming; blank is refused.
positiontextYesMax 120 characters after trimming; blank is refused.
isDefaulttextNo"true" or "false" (any case). Omitted or blank means false. true makes this the company default and clears the previous one.

Response 201

The new signature object. This one is 201, not 200. There is no Location header.

{
  "id": "sig_123",
  "name": "Jane Example",
  "position": "Managing Director",
  "isDefault": true,
  "createdAt": "2026-01-15T08:30:00Z",
  "createdByName": null
}

Errors

The 400 bodies here use { "error": "message" }.

  • 400 { "error": "isDefault must be \"true\" or \"false\"." }
  • 400 { "error": "Enter the signatory's name." } — also "Enter the signatory's position." and "Keep the name to 120 characters or less." (or position).
  • 400 { "error": "Choose an image file (PNG, JPG or WebP) for the signature." } — no file part, or it is empty.
  • 400 { "error": "The signature image is larger than 1 MB. Use a smaller image." }
  • 400 { "error": "The signature must be a PNG, JPG or WebP image." } — any other format.
  • 400 { "error": "The signature image is 5000 × 3000 pixels. Keep each side to 4000 pixels or less." } (the message carries the real size).
  • 400 { "error": "That image can't be read. It may be damaged — try saving it again." }
  • 400 { "error": "A company can keep up to 10 signatures. Remove one first." } — removed signatures don't count.
  • 403 — the key lacks organizations:write.
  • 413 — the whole request body is over 2 MB. This is a hard cap checked before the 1 MB rule, so a file between 1 and 2 MB gets the 400 message above and a larger one gets 413 with no JSON body.
  • 415 — the request isn't multipart/form-data.

Things that bite

  • The first signature becomes the default whatever isDefault says. After that it is only the default when you ask.
  • Check order. isDefault is checked first, then name and position, then the image, then the limit of 10.
curl -X POST https://<api-host>/organizations/current/signatures \
  -H "Authorization: Bearer wp_live_xxx" \
  -F "file=@signature.png" \
  -F "name=Jane Example" \
  -F "position=Managing Director" \
  -F "isDefault=true"
PUT /organizations/current/signatures/{id} organizations:write

Edit a signature's name and position, and say whether it is the company default. The image can't be changed: add a new signature and remove the old one.

This PUT replaces all three fields. An omitted isDefault is read as false, so sending only name and position for the current default unsets it and leaves the company with no default. Read the signature first and send everything back. No other signature is promoted when the default is unset.

Request body

FieldTypeRequiredLimits

positionstringYesMax 120. Trimmed; blank is refused.
isDefaultbooleanNo (default false)true makes it the company default and clears the previous one.

The saved signature object.

Errors

  • 400 { "errors": { … } } — name or position missing or over 120 characters (as sent).
  • 400 { "error": "Keep the name to 120 characters or less." } — also "Enter the signatory's name." / position versions, when the value is blank or too long after trimming.
  • 403 — the key lacks organizations:write.
  • 404 — empty body; no such signature in this company, or it has been removed (including a remove that landed just before this call).

Letters already kept on file keep the name they were printed with.

curl -X PUT https://<api-host>/organizations/current/signatures/sig_123 \
  -H "Authorization: Bearer wp_live_xxx" -H "Content-Type: application/json" \

DELETE /organizations/current/signatures/{id} organizations:write

Remove a signature. It stops being listed, served or printed, and its image file is deleted.

Response 204

Empty body.

Errors

  • 403 — the key lacks organizations:write.
  • 404 — empty body; no such signature, or it is already removed. Unlike the logo, a repeat is not a 204.

Things that bite

  • Removing the default leaves no default. No other signature is promoted. A Documents letter then prints no signature image unless a template default or a signatureId names one.
  • It can't be undone. The row is kept only for the activity log and for letters on file that name it; the image is gone, so add the signature again to use it.
  • Templates that defaulted to it read as having no default signature (defaultSignatureId is null), and their letters fall back to the company default. Sending its id as signatureId on Documents is a 400.
curl -X DELETE https://<api-host>/organizations/current/signatures/sig_123 \
  -H "Authorization: Bearer wp_live_xxx"

Administrators

These two endpoints live under /admin but are called with the same wp_live_ company key as everything else, not a master key. The key decides which company they act on, so a caller can only ever make an administrator of the company it already integrates with.

Roles here are "Owner" and "Admin". An Owner is a company's top administrator; everyone else with admin access is an Admin.

POST /admin/admins organizations:write

Make an email address an administrator of the company. This is the explicit step to take when POST /sso/ticket answers 404 because that email isn't an admin yet: grant, then retry the ticket.

Request body

FieldTypeRequiredMeaning
emailstringyesA valid email address. Surrounding spaces are trimmed.
namestringnoMax 120 characters. Used only when a new account is created; when blank, the part of the email before @ is used.

Response 200

200 in every success case, including when nothing changed.

FieldTypeMeaning
emailstringThe account's email.
createdbooleantrue when no account existed for this email and one was made.
linkedbooleantrue when this call gave the account an admin seat in the company. false when it already held one.
rolestringThe seat the account holds now: "Owner" or "Admin".
 
{ "email": "jane@example.com", "created": true, "linked": true, "role": "Owner" }

Errors

  • 400 { "errors": { … } } — email missing or not an email address, or name too long.
  • 403 — the key lacks organizations:write.

Things that bite

  • The first administrator becomes the Owner. If the company has nobody administering it yet, the person you grant is its Owner; everyone after that is an Admin.
  • Safe to retry. Someone who is already an Owner or Admin is left exactly as they are (linked: false, their existing role).
  • It can promote. An existing employee of the company is moved into the admin seat; their account and history stay.
  • Accounts are matched by email across companies. If the email already has an AltomateHR account elsewhere, it is reused and gains a seat here (created: false, linked: true). A newly created account has no password. It's meant to be entered through the sign-in hand-off.
curl -X POST https://<api-host>/admin/admins \
  -H "Authorization: Bearer wp_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "email": "jane@example.com", "name": "Jane Example" }'

Single sign-on hand-off

Lets your platform drop one of the company's administrators into AltomateHR already signed in, with no AltomateHR password. It's two steps: your server asks for a ticket with the key, then the administrator's browser opens the callback with it. Only the first step is an API call.

GET /whoami lists sso.inbound in features on a deployment that supports this.

POST /sso/ticket sso:write

Mint a one-time sign-in ticket for an Owner or Admin of the key's company. The person comes from the body; the company is always the key's own.

Request body

FieldTypeRequiredMeaning
emailstringyesA valid email address of an Owner or Admin of this company, matched case-insensitively.

Response 200

FieldTypeMeaning
ticketstringAn opaque, single-use ticket.
redirectPathstringThe path to send the person's browser to: /sso/callback?t=<ticket>. It's relative to the API host, so prefix it with the host you call.
expiresInintegerSeconds the ticket stays valid: 120.
 
{
  "ticket": "tkt_xxx",
  "redirectPath": "/sso/callback?t=tkt_xxx",
  "expiresIn": 120
}

Errors

  • 400 { "errors": { … } } — email missing or not an email address.
  • 403 — the key lacks sso:write.
  • 404 { "message": "No admin or owner with that email in this organization." } — one answer for no such person, a person in another company, and a person who isn't an Owner or Admin. Call POST /admin/admins to give them a seat, then retry.
Mint the ticket when the person clicks, not ahead of time. It works once and dies after 2 minutes. It's also checked again when it's used, so an admin seat revoked in the meantime no longer works. 
curl -X POST https://<api-host>/sso/ticket \
  -H "Authorization: Bearer wp_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "email": "jane@example.com" }'
GET /sso/callback?t=<ticket> Browser redirect, no key

Not an API call. Redirect the administrator's browser to the redirectPath from the previous step. The ticket is the credential, so this takes no Authorization header.

  • Valid ticket: the browser is redirected into AltomateHR, signed in as that administrator in the key's company. Nothing sensitive is in the URL.
  • Used, expired, forged or missing ticket: the browser is redirected to the ordinary sign-in page with sso=expired in the query, the same as arriving signed out. Mint a new ticket.

The redirect always goes to AltomateHR's own address, never to one you supply.

Not available to API keys

Listing admins and setting their module access (GET /organizations/admins, PUT /organizations/admins/{userId}/access), editing an admin's name and login email (PUT /organizations/admins/{userId}), removing an admin (DELETE /organizations/admins/{userId}), creating a company (POST /organizations) and changing a company's plan (PUT /organizations/{organizationId}/plan) answer 403 to any key.
