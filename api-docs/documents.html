Documents

HR letters. A company keeps a library of letter templates (offer, confirmation, resignation, warning, …) with {{merge.fields}} in the text; you generate a PDF letter for one employee at a time, filled from their record, and optionally keep a copy on their file. Every endpoint is for admins and keys only — employees never see these letters.

Access

  • Scopes. documents:read lists templates and letters on file and renders previews; documents:write edits templates and generates or deletes letters.
  • Module gate. Every endpoint needs the organization's plan to include the documents module, else 403 with This organization's plan does not include the 'documents' module.
  • Employee ids. employeeUserId is the user id from GET /employees (see Employees), not the payroll employeeProfileId.
A letter reads the employee's record (IC, address, salary), so the actions that touch an employee also need an Employees scope on the key, on top of the Documents scope. Without it the call answers 403 { "error": { "status": 403, "message": "Caller is missing required scope: employees:read." } } (or employees:write). employees:write is only counted when the key also has employees:read.

Errors on this page use these shapes: validation failures { "errors": { "Field": ["…"] } } (e.g. a missing or too-long name); business-rule refusals { "message": "…" }, sometimes with a list of fields (unknownFields or missingFields, null when it does not apply); 403 { "error": { "status": 403, "message": "…" } }; and an empty 404 for something that is not in this company. A 404 is also what an employee outside the key's reach looks like. Where an endpoint lists only some of these, the others cannot occur.

Merge fields

A template body can use {{key}} placeholders. The registry below is the full list; a template that uses any other key (other than {{input.name}}) is refused on save.

Besides the registry, a template may use ad-hoc {{input.someName}} fields (a letter or letter-by-letter detail such as a last working day). The name is a letter followed by up to 59 letters, digits or underscores. Nothing on file answers them, so you supply a value in values when generating. Their kind is guessed from the name: ending in date or day is a Date, ending in amount or salary is Money, otherwise Text. 

curl https://<api-host>/documents/merge-fields \
  -H "Authorization: Bearer wp_live_xxx"

Templates

A template's body is a small markdown subset: a blank line ends a paragraph; # Heading and ## Smaller heading; - item bullets; **bold**; and {{merge.fields}}. A single line break inside a paragraph is kept (good for address blocks). Merge values are inserted as literal text, so a value containing ** never becomes formatting. The PDF prints the letter date, the company name and the signature block itself, so don't repeat them.

POST /documents/templates/import documents:write

Convert a Word, text or markdown file into template markup. Nothing is saved: the result is for review, and you save it with create.

Request

multipart/form-data with one part named file: a .docx, .txt or .md (also .markdown) up to 5 MB. Text files must be UTF-8. Old .doc files are refused.

What a .docx keeps: paragraphs, headings (Title and Heading 1 become #, lower headings ##), bold, bulleted and numbered lists (as bullets), tables (one paragraph per row, cells joined by | ), {{placeholders}}, and Word mail-merge fields (MERGEFIELD Name becomes {{Name}}). Images, text boxes, headers, footers and footnotes are dropped and reported in warnings.

Response 200

FieldTypeMeaning
suggestedNamestringThe first heading, else the file name.
bodystringTemplate markup.
unknownFieldsstring[]Placeholders in the text that are neither a registry key nor a valid {{input.name}}, as written (e.g. "Employee Name"). Create refuses a body that still contains them — replace each with a key from the registry first.
warningsstring[]What did not come across, e.g. skipped images.

Errors

400 { "message": "…" } — no file or an empty file ("Pick a Word (.docx), .txt or .md file to upload."), unsupported type, larger than 5 MB, unreadable or non-UTF-8 file, or no text found. The server refuses a request body over 8 MB before it gets that far.

curl -X POST https://<api-host>/documents/templates/import \
  -H "Authorization: Bearer wp_live_xxx" \
  -F "file=@offer-letter.docx"

Preview, resolve and generate

The rule: a letter never goes out with a blank where a detail should be. Every field the template uses is looked up in the records first; resolve shows what was found and what is missing, and generate refuses until every gap is filled for that letter or explicitly left blank. Four fields are needed by every letter whether or not the body mentions them, because the PDF prints them: today, company.name, signatory.name and signatory.position. The company and signatory ones come from Payroll → Settings → Form E (LHDN) → Employer details (the declarant is the default signatory); a key can set them with PUT /payroll/company-info on the Payroll page. The letter date is today in Malaysia time.

POST /documents/templates/{id}/generate documents:write also employees:read

Generate the letter as a PDF for one employee, and by default keep a copy on their file.

Request body

FieldTypeRequiredMeaning
employeeUserIdstringYesMax 40. User id.
valuesobject (string → string | null)NoPer-letter values keyed by merge key: what you typed for a missing field, an input.* field, or an override of a value on file. Dates as yyyy-MM-dd, money as a number; both print in letter form. Blank values count as not supplied. Max 2,000 characters each. A typed value wins over the record.
leaveBlankstring[]NoKeys you deliberately leave empty. Any other field with no value refuses the letter.
saveToEmployeestring[]NoKeys of missing writable employee fields (writableToEmployee in the registry) whose typed value should also be written to the employee's record. Needs employees:write. A key that is not writable, not used by the template, already has a value on the record, or has no typed value, is skipped without error.
savebooleanNo (default true)Keep a copy on the employee's file (see letters on file). false returns the PDF and stores nothing.

Response 200

Content-Type: application/pdf, filename {template name} - {employee name} - {yyyy-MM-dd}.pdf, Cache-Control: no-store. The body is the PDF, not JSON, so the saved letter's id is not returned — fetch it from GET /documents/generated?employeeUserId=…. It is 200, not 201.

Side effects. With save on (the default) every call stores another copy; repeating a request creates a duplicate letter on file. saveToEmployee writes to the employee's record, but only into fields that are empty there — it never overwrites — and it does not mark payroll drafts stale (none of these fields feed a payroll calculation). Both generating and deleting a letter are written to the audit log.

Errors

  • 400 { "message": "Fill in these details, or choose to leave them blank, before generating: Confirmation date, Signatory name.", "missingFields": ["employee.confirmationDate", "signatory.name"] } — gaps remain. Nothing was saved or written.
  • 400 { "message": "…", "missingFields": null } — a typed value is over 2,000 characters; the template uses merge fields that no longer exist (edit it first); or a saveToEmployee value is invalid (employee.probationMonths must be a whole number 0–120, employee.confirmationDate must be yyyy-MM-dd).
  • 403 — missing employees:read, or saveToEmployee sent without employees:write. The request is refused outright, never partly done.
  • 404 — no such template, or the person is not a member of this company.
curl -X POST https://<api-host>/documents/templates/tpl_123/generate \
  -H "Authorization: Bearer wp_live_xxx" -H "Content-Type: application/json" \
  -d '{"employeeUserId":"emp_123","values":{"employee.confirmationDate":"2026-11-01"},"saveToEmployee":["employee.confirmationDate"],"save":true}' \
  -o letter.pdf

Copies kept by generate. They are admin-only: they are not the employee documents attached to a profile and never appear in the employee's own portal. Each endpoint here also needs employees:read on a key, since a kept letter is the employee's record in print.
