Attendance

Read a company's attendance records, worked-hours totals and approval trail, load historical days from another time clock, and manage the shifts and public holidays that decide what counts as a normal working day.

Clocking in and out is for people, not keys (see Not available to API keys). A key reads the whole company's records and reports, and administers shifts, holidays and imports. Dates are ISO 8601; instants in responses are UTC with a trailing Z; ids are strings. Every employeeId on this page is the user id that GET /employees returns as id.

Scopes, gates and errors on this page

The three controllers are not gated the same way:

GroupRead scopeWrite scopePlan module (403 if missing)
/attendance/…attendance:readattendance:writeattendance
/shifts/…attendance:readattendance:writenone checked
/holidays/…attendance:readorganizations:writenone checked
  • Shifts have no scopes of their own; they use the attendance ones.
  • Public-holiday reads use attendance:read but writes (create, edit, import, delete) need organizations:write, not an attendance scope. A key that can write attendance cannot write holidays unless it also holds that scope.
  • Every endpoint here also needs the key's admin rights, which a key always has.
A fourth error shape. Beyond the three on the overview, most 400s from these three controllers are { "message": "…" } (not { "error": "…" }). Read message when error is absent. Field-validation failures still come back as { "errors": { "Field": ["…"] } }, and a missing scope or module as { "error": { "status": 403, "message": "…" } }. A 404 is an empty body unless noted.

Attendance records & reports

An attendance record is one employee's day. A day can hold several clock-in/clock-out stints (sessions); the record's own timeIn, timeOut and durationMin are the roll-up of them.

Some endpoints act as "the caller", and a key has no attendance of its own. A key's identity is not an employee, not on any team and not in any approval chain (admins are never in the approval hierarchy). So GET /attendance/today and /open-session return 204, /hours-summary/me returns zeros, and the team queues and approval actions on the Approvals section return empty lists or 404. They are documented for completeness; use the company-wide endpoints instead.

Endpoints that read as "the caller" (empty for a key)

GET /attendance/today attendance:read

The calling user's record for today. For a key: always 204 (no body). Module gate: attendance. For anyone else's day, filter GET /attendance by employeeId and date.

GET /attendance/open-session attendance:read

GET /attendance/team/today attendance:read

Today's attendance of the calling user's direct reports, per project and team. For a key: always [], because a key supervises no team. Module gate: attendance.

Approvals (records and breaks)

Every clock-in, clock-out, break start and break end creates an approval request that its employee's approvers decide step by step, along their team's approval chain. A correction an employee asks for on a clock time is a clock-in or clock-out request that also carries originalEventAt and reason; it changes the record only once fully approved.

A key cannot decide approvals today. These endpoints are open to keys (they pass the scope and role checks) but they act as the caller, and "who may approve" is a seat in the employee's approval chain. A key is never in a chain, so for a key the queues below are empty, approve and reject answer 404 for every id, and the bulk calls report every id as "Not found.". Use approval-audit and audit-log to read the trail.

Approve a clock-in or clock-out request. No body.

Module gate: attendance. id is an approval request id of kind CLOCK_IN or CLOCK_OUT, not a record id and not a break request.

Import

Load historical daily records from another time clock. It is a migration tool, not a second way to clock in: no geofence, IP or photo checks apply, no approval requests are created (so a year of history doesn't land in anyone's queue), and a day the employee already has a record for is skipped, never overwritten.

The status can be 200 with nothing imported. An empty file, a header with no data rows, or a missing required column comes back 200 with imported: 0, failed: 0 and one errors entry on row 1 — check errors, not just the status. Re-uploading a corrected file is safe: rows that landed are skipped.

Shifts

A shift is a named work schedule belonging to one project: start and end time, working days and an unpaid lunch break. An employee's shift sets their scheduled start (for lateness) and their standard daily minutes (for the hours buckets). Reads need attendance:read and writes attendance:write; the plan's attendance module is not checked on these routes. Assigning a shift to an employee is done on the employee, not here.
