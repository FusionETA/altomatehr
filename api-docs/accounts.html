Accounts

The company's chart of accounts. Employees file claims against an account; an account can carry a spend limit and a mileage rate, and can be switched off for claims or archived. Bank accounts are what a company-paid claim is paid from.

Accounts

Needs the accounts module on the company's plan — every endpoint below answers 403 with This organization's plan does not include the 'accounts' module. otherwise.

The account object

FieldTypeMeaning
idstringAccount id.
codestringAccount code, e.g. "6100".
namestringDisplay name, e.g. "Travel Expenses".
typestring"EXPENSE" (what a claim is coded to), "BANK" (what a company-paid claim is paid from) or "LIABILITY" (payroll payables such as EPF or net salary; never offered for a claim). You can only create or save EXPENSE and BANK; LIABILITY accounts are only returned when asked for.
xeroAccountIdstring | nullXero's id for the account, when it came from a Xero sync. Null for an account made by hand.
xeroStatusstring | nullStatus as last synced from Xero, e.g. "ACTIVE".
xeroTypestring | nullXero's own account type as the last sync saw it (e.g. "EXPENSE", "OVERHEADS"). Null for a hand-made account, and for a Xero one until its next sync.
xeroSyncedAtstring (ISO 8601) | nullWhen Xero last synced this row.
isSelectablebooleanWhether employees can file claims against it. Always false for a LIABILITY account.
limitAmountnumber | nullOptional spend limit per claim, in MYR. Null means no limit.
allowMileageClaimbooleanWhether mileage claims can be filed against this account.
mileageRatenumber | nullRate per distance unit (the company's mileage unit, km by default) for mileage claims on this account. Null or 0 falls back to the company's default mileage rate.
isArchivedbooleanSoft-archived. An archived account can't be chosen on a new claim, but the row stays for past claims to reference.
A claim over its account's limitAmount isn't refused; it's flagged as exceeding the limit.
GET /accounts accounts:read

The company's chart of accounts, ordered by code. Archived accounts and accounts with isSelectable: false are included, so filter on those fields if you only want what a claim can use.

Creating, updating & archiving

These require the Admin role, which an API key always holds in its own company. Each one is written to the company's activity log.

POST /accounts accounts:write

Creates an account by hand.

Refused with 409 while the company is connected to Xero: Xero owns the chart of accounts then, and accounts arrive by syncing from Xero instead.

Response 200

The new account object (status is 200, not 201).

Errors

  • 400 — { "errors": { "Code": ["..."] } } when a field fails validation, including a type other than EXPENSE or BANK.
  • 409 — { "message": "Xero owns the chart of accounts while it's connected. Sync from Xero instead of adding an account here." }. Note the key is message, not error.
curl -X POST https://<api-host>/accounts \
  -H "Authorization: Bearer wp_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "6100",
    "name": "Travel Expenses",
    "type": "EXPENSE",
    "isSelectable": true,
    "limitAmount": 500.00,
    "allowMileageClaim": true,
    "mileageRate": 0.60
  }'
PUT /accounts/{id} accounts:write

Updates an account, including its spend limit and mileage settings. This is a full replace, not a merge: every field is overwritten with what you send, so a field you leave out goes back to its default (limitAmount and mileageRate to null, allowMileageClaim to false, isSelectable to true, type to "EXPENSE"). Read the account first and send it back with your change.

Still allowed while the company is connected to Xero. Unlike create, update isn't blocked by the Xero connection.
A LIABILITY account stays a liability and stays unselectable: its type and isSelectable in the body are ignored. Its code, name, limit and mileage fields are still written.

Request

{id} is the account id from GET /accounts. The body is the one described above.

Response 200

The updated account object.

Errors

  • 400 — { "errors": { "Name": ["..."] } } when a field fails validation.
  • 404 (empty body) — no account with that id in this company.
curl -X PUT https://<api-host>/accounts/acc_123 \
  -H "Authorization: Bearer wp_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "6100",
    "name": "Travel Expenses",
    "type": "EXPENSE",
    "isSelectable": true,
    "limitAmount": 800.00,
    "allowMileageClaim": true,
    "mileageRate": 0.60
  }'
POST /accounts/{id}/archive accounts:write

Archives an account, so it can no longer be chosen on a new claim. Nothing is deleted: past claims keep pointing at it. No body. Archiving an already-archived account succeeds and changes nothing.

Response 200

The account object with isArchived: true.

Errors

404 (empty body) — no account with that id in this company.

curl -X POST https://<api-host>/accounts/acc_123/archive \
  -H "Authorization: Bearer wp_live_xxx"
POST /accounts/{id}/restore accounts:write

Brings an archived account back. No body. Restoring an account that isn't archived succeeds and changes nothing.

Response 200

The account object with isArchived: false.

Errors

404 (empty body) — no account with that id in this company.

curl -X POST https://<api-host>/accounts/acc_123/restore \
  -H "Authorization: Bearer wp_live_xxx"

Not available to API keys
